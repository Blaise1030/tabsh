# Solid UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace VanJS with Solid across `web/src/app` — every view a typed TSX component, every list `<For>`, every state owned and disposed — with behaviour, CSS, selectors, URLs and the daemon unchanged.

**Architecture:** The existing VanJS states stay canonical while the UI moves, and Solid reads them through a memoised `fromVan` accessor, so no unmigrated feature changes behaviour. The shell becomes Solid first and renders the same ids; features then migrate subtree by subtree. A final mechanical slice flips all state to `createSignal` and removes the bridge. `nav/router.ts`, xterm, CodeMirror and `@pierre/trees` are untouched apart from their hosts.

**Tech Stack:** TypeScript (strict, `astro check`), `solid-js` 1.9.x, `@astrojs/solid-js` 7.1.x (`vite-plugin-solid` 2.11, Vite 8), Basecoat (CDN), `node --test`, Playwright e2e against a real daemon, Rust tests in `src/web/`.

**Spec:** `docs/superpowers/specs/2026-10-21-solid-ui-design.md`

## Global Constraints

- New dependencies exactly: `solid-js@^1.9.17` and `@astrojs/solid-js@^7.1.0`. No `solid-devtools`, no `@solidjs/router`, no `@solidjs/testing-library`. Remove `vanjs-core`, `react` and `react-dom` in Task 12.
- Every e2e spec passes **unedited** (29 specs). The only allowed edit is a selector reaching into removed VanJS internals, with a comment saying why; none is expected.
- No `innerHTML`, `outerHTML` or `insertAdjacentHTML` anywhere in `web/src/app`, now including `.tsx`.
- User text stays a child string or an attribute value. No markup strings.
- Preview sandboxes unchanged: HTML `allow-scripts allow-popups`; Markdown and SVG `sandbox=""`; images and PDFs from `blob:` URLs.
- CSP and `web/public/_headers`/`APP_CSP` unchanged: handlers are properties, no inline `<script>`, no `on…=` attributes.
- The editor, tree and QR stay lazy: `files/pane.tsx`, `files/editor.ts`, `marked`, `@pierre/trees` and `uqr` only behind `import()`; `entry_script_does_not_bundle_the_editor` stays green.
- Pure modules that `node --test` loads must not touch the DOM when imported. Tests stay `.ts`; components are `.tsx`.
- Every id, class and element type an e2e spec or `app.css` uses survives.
- VanJS stays canonical until Task 11. A Solid component reads VanJS state only through `fromVan`.
- Before each e2e run: `cd web && npm run build`, then `cd .. && cargo build --locked` (the daemon embeds the app). Never commit `src/app.html` or `src/app-assets/` before Task 12; restore them with `git checkout -- src/app.html src/app-assets` and remove new files by exact name. Never run `git clean`.
- Checks before each commit, in `web/`: `npm run check`, `npm run lint`, `npm test`, plus the task's e2e group. At Tasks 1, 6, 9 and 12 run the full suite.
- Comments are short prose, no JSDoc. Commit style matches the repo: `refactor(web): …` or `feat(web): …`.

## Review Focus

1. **A child control's event also fires its ancestor.** The tab close button, a card's menu button, a menu row and the palette's rows all sit inside a clickable parent; Solid's delegated `click`/`keydown` would run both handlers. Owner: Tasks 5, 6, 7. Pinned by `tabs` (close), `board` (`a card menu opens on right-click or from the keyboard, with no menu button`; `a card's Move menu sets its status`), `palette`.
2. **Focus or fit after a switch.** Removing the microtask waits can leave the terminal unfocused, or sized for the old view, after a tab, side terminal, board or drawer change. Owner: Tasks 4, 5, 6. Pinned by `tabs`, `side-terminals`, `replay`, `board` (`a card opens its terminal in a drawer beside the board`).
3. **A close animation, a re-add, or a drag during an update.** A closing tab must collapse and go, its copies with it; a tab renamed mid-drag must keep the drag. Owner: Task 5. Pinned by `tabs` (`closing a tagged tab removes its copies`; `a rename mid-drag keeps the drag`).
4. **A host recreated or duplicated.** A second xterm, CodeMirror or tree instance loses scrollback, edits or the tree's state. Owner: Tasks 4, 8, 9. Pinned by `replay`, `pane` (`a theme change keeps the edit and the dirty dot`), `explorer-live` (`the tree stays current as files change on disk`).
5. **Basecoat's cached palette state after a page change.** New rows must be filterable and arrow-navigable. Owner: Task 7. Pinned by `palette` (`arrow keys work after changing page`).

## Shared Interfaces

```ts
// web/src/app/ui/interop.ts — TEMPORARY, deleted in Task 12.
import type { State } from 'vanjs-core';
import type { Accessor } from 'solid-js';

/** A Solid accessor following a VanJS state; one mirror per state object. */
export function fromVan<T>(state: State<T>): Accessor<T>;
```

`toVan` from the spec is not built: under the state-last order no Solid state
needs to be read by a VanJS view. If a seam ever needs it, add it in that
task rather than here.

```ts
// web/src/app/ui/presence.ts — pure, node-testable.
/** The next list with removed keys re-inserted at their old index, clamped. */
export function mergePresence<T>(prev: T[], next: T[], by: (t: T) => string): T[];
```

```tsx
// web/src/app/ui/presence.tsx
export function Presence<T>(props: {
  each: T[];
  by: (t: T) => string;
  /** Resolves when the item's leave animation has finished. */
  exit: (item: T) => Promise<void>;
  children: (item: T) => JSX.Element;
}): JSX.Element;
```
