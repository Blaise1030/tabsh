# Declarative UI with VanJS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every view in the tabsh web app is a VanJS component that reads like its markup and updates itself from state; `el()`, `#tab-template`, `render()` and hand-synced `hidden`/class/`aria-*` are gone, with behaviour unchanged.

**Architecture:** `index.astro`'s body becomes one mount point; `main.ts` mounts `App()` (in `ui/app.ts`) before anything else runs. Each feature exports its own `van.state`s; the navigation router's steps (`onPlace`) assign them and components derive from them. Lists go through a small `ui/keyed.ts`. xterm, CodeMirror and `@pierre/trees` stay imperative inside hosts their component creates once.

**Tech Stack:** TypeScript (strict, `astro check`), `vanjs-core` 1.6.x (npm, bundled), Basecoat (CDN, unchanged), `node --test`, Playwright e2e against a real daemon, Rust tests in `src/web/`.

**Spec:** `docs/superpowers/specs/2026-10-07-vanjs-ui-design.md`

**Prerequisite:** the URL navigation branch (`feat/url-navigation`, plan `2026-10-07-url-navigation.md`) has all its tasks done and is open as a PR to `main`. This work is a stacked branch, `feat/vanjs-ui`, cut from `feat/url-navigation` (carry over this plan's and the spec's commits), and its PR targets `feat/url-navigation`; once navigation merges, retarget it to `main`. Locate code by symbol: the navigation work moves lines in every file below.

## Global Constraints

- One new dependency only: `vanjs-core` (`^1.6.1`), imported as `import van from 'vanjs-core'`. No `vanjs-ext`, no DOM test library.
- No `innerHTML`, `outerHTML` or `insertAdjacentHTML` anywhere in `web/src/app` once Task 10 lands; no new ones in any task.
- User text (tab names, notes, tags, paths, file names, card titles) is only ever a child string or an attribute value.
- States are assigned whole (`s.val = next`), never mutated in place.
- Every element id in today's `index.astro` survives with the same element type, and every class name an e2e spec or `app.css` uses survives (`.tab`, `.mirror`, `.active`, `.tab-group`, `.tab-group-box`, `.board-card`, `.board-col`, `.board-onboarding`, `.pane-head`, `.term`, …).
- Existing e2e specs pass **unedited** after every task. The only allowed edit is a selector into `#tab-template` internals, with a comment saying why.
- Preview sandboxes unchanged: HTML `sandbox="allow-scripts allow-popups"`; Markdown and SVG `sandbox=""`; images and PDFs from `blob:` URLs.
- CSP, `web/public/_headers` and `APP_CSP` unchanged: handlers are properties, never `on…=` attributes; no inline `<script>`.
- The editor and the tree stay lazy: `files/pane.ts`, `files/editor.ts`, `marked` and `@pierre/trees` are only reached through `import()`; `entry_script_does_not_bundle_the_editor` stays green.
- `nav/` imports neither `vanjs-core` nor any feature. Pure files `node --test` loads must not touch the DOM when imported.
- Comment and naming style matches the surrounding code: short prose comments, no JSDoc.
- Checks before each commit, in `web/`: `npm run check`, `npm run lint`, `npm test`, and the task's e2e specs (`npm run build` and `cargo build` first; the daemon embeds the app). Never commit `src/app.html` or `src/app-assets/` before Task 10; restore them with `git checkout -- src/app.html src/app-assets` and delete untracked files in `src/app-assets/` by exact name. Never run `git clean`.

## Review Focus

1. **A tab closing while grouped by tag with copies** (`.mirror`): the tab and every copy run their collapse animation, then disappear; no copy lingers. Pinned in Task 4 (e2e `closing a tagged tab removes its copies`).
2. **Dragging a tab while a daemon update re-renders the strip** (a rename or status change mid-drag): the dragged node is not torn out from under the pointer. Pinned in Task 3 (`keyed` keeps a node whose key survives) and Task 4 (e2e `a rename mid-drag keeps the drag`).
3. **Module-level DOM lookups running before `App()` is mounted** (`palette.ts`, `daemon/client.ts`): the page must not throw on load. Pinned in Task 2 (smoke e2e plus the gate e2e).
4. **The palette's Basecoat state after a page change** (stale cached items): arrow keys and filtering work on the new page's items. Pinned in Task 6 (e2e `arrow keys work after changing page`).
5. **A file reopened after a theme change in preview mode** (Markdown frame re-themed, editor re-themed): no duplicate frames, no lost dirty dot. Pinned in Task 8 (e2e `a theme change keeps the edit and the dirty dot`).
